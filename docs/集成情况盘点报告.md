# 集成情况盘点报告 — 26 个下载仓库 vs 实际集成

> **审查时间**：2026-08-11
> **审查范围**：`ai-webnovel-repos/` 下全部 26 个仓库 + `.claude/` 内项目自有资产
> **审查方式**：4 路并行盘点（21 agent-systems 能力 / 5 skills 能力 / 项目内引用穷举 / webnovel-writer plugin 改造深挖）
> **核心问题**：用户原话"下载了很多工具集成进来，取其精华去其糟粕"——实际做到了几分？

- 项目对外宣传的"取其精华去其糟粕"**并未真正兑现**——绝大多数仓库从未被读过（连 README 都没在文档里被引用过）

## 6. 5 个"待决策"问题（给你 review 用）

### Q1：snapshot 目录是否清理？

`.claude/sources/tianming-skill/` 和 `.claude/sources/novel-writing-toolkit/` 在 `.gitignore` 里但**占磁盘**。如果不打算 fork 它们的代码：
- **建议**：删除这两个目录

### Q2：novel-creator-skill 的 RAG + 知识图谱要不要吸收？

现有项目 CHANGES 校验 + anti-slop 双引擎跑通了，但**单章节级**一致性能守住，**长线一致性**（跨 50 章/100 章）目前是裸奔。novel-creator-skill 的 `plot_rag_retriever.py` + `story_graph_builder.py` + `event_matrix_scheduler.py` 是被验证能跑 300 万字的核心组件。
- **现状**：项目现在每章 2000-2500 字，离 300 万字还远
- **决策点**：现在补 vs 写到 50 万字再补 vs 不补（接受长线漂移风险）

### Q3：oh-story-claudecode 的 `story-import` 要不要做？

把"已有小说 → 续写工程"反向解析是现有项目**完全没有**的能力。skill 仓库里有现成实现（CDP 协议爬虫 + 章节提取 + 角色/设定/伏笔反推）。
- **价值**：极大（解决用户最痛的"已有底稿如何续写"问题）
- **代价**：高（需要重构数据模型适配本地 CHANGES 协议）

### Q4：`references/aesthetic/` 3 个文件（298 行）死代码要不要复活？

`ai-word-blacklist.md` / `anti-ai-quick-ref.md` / `writing-edicts.md` 在 plugin 目录里**没有任何 skill 引用**。
- **可能性 a**：准备接进 `webnovel-write` Step 4 polish 但还没接
- **可能性 b**：本意放在 `设定集/` 模板里被 init 复制
- **可能性 c**：死代码
- **建议**：要么接进 webnovel-deslop-check 的 references/，要么删除

### Q5：剩余 18 个 agent-systems 仓库要不要逐个盘点？

现状：完全未读（连 README 都没引用过）。
- **路径 A**：批量盘点（每个仓库 30 行摘要 = 540 行文档），决定哪些值得深度借鉴
- **路径 B**：直接清理，只保留 webnovel-writer + novel-creator-skill + oh-story-claudecode + tianming（如果保留 snapshot）

## 7. 总结判断

**"取其精华去其糟粕"实际做到的程度：**

- ✅ **做到了的部分**：
  - 把 `webnovel-writer` v6.2.1 这个最有体系的 skill 整体接住
  - 在它基础上做了**有意识的能力扩展**（foreshadowing 聚合、style 注入、Ω 级硬规则）
  - 选对了 anti-slop 双引擎来源（novel-creator-skill + oh-story-claudecode 两个 MIT 仓库互补）

- ❌ **没做到的部分**：
  - 26 个仓库中**只有 2 个被真实 fork**（且只 fork 最表层 6 个文件）
  - 22+ 个仓库**完全闲置**——既没读过，也没清理，纯粹占磁盘
  - novel-creator-skill 的**真正精华**（RAG / 知识图谱 / 进度配额 / 反向刹车）**一个都没拿**
  - oh-story-claudecode 的**核心能力**（story-import / 8 hooks / 100+ refs / Agent 模型调度）**一个都没拿**
  - tianming snapshot 借用字段定义却没复制任何代码，snapshot 也只在 `.gitignore` 占空间

- ⚠️ **判断风险**：
  - 如果项目目标是"工具集成"——**集成度严重不足**，22 个仓库是浪费
  - 如果项目目标是"基于 webnovel-writer 做能力扩展"——**做得不错**，但**别再用"取其精华"宣传自己**，因为没怎么取
  - 如果项目目标是"自己的写小说方法论"——**方向清晰**（CHANGES 协议 + anti-slop + 写作铁律），但与外部仓库**几乎无血缘关系**，独立产品的可能性更大

**建议**：
1. 短期：清理 22 个未用仓库的 snapshot（Q5 路径 B）
2. 中期：决定是否吸收 novel-creator-skill 的长线一致性组件（Q2）
