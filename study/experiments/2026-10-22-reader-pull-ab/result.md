# Reader Pull 单变量实验：结果

日期：2026-10-23
基线：`main` @ `35c5a4b`（含 PR #59）
分支：`fix/reader-pull-layer`
判定：**`READER_PULL_LAYER_SUPPORTED`**（仅在“追读”维度上成立，文学克制维度证据分裂，见“限制”）

---

## 一、单变量是什么

两稿来自**同一个已封口的 Writer Package**，指纹都是
`3063af5b46ab8f5cd83d9ba97ec8775e205af97b1e1e19f3af250225b6cff5c5`。

固定的东西：同一本书、同一份 Canon、同一个章号与章目标、同一份 Creative Brief、
同一份 Scene 设计（`--scene-design`）、同一个 Writer 模型与参数、同一个字数区间、
同一套人物状态与信息边界。B 稿**没有**获得任何额外的剧情素材。

唯一变量是 `runtime attach-creative-brief` 的 `--reader-pull`：

| | A（对照） | B（实验） |
|---|---|---|
| 章末钩子字段 | 渲染 `章末钩子/未决问题` 与 `预设钩子设计`（含钩子类型） | 不渲染 |
| 题材配置 | 整段 `mystery` YAML（`hook_config` / `coolpoint_config` / `micropayoff_config` / `pacing_config` / `override_config`）原样进入 Prompt | 剥离 |
| 前情摘要 | 带 `hook_type: "悬念式"` / `hook_strength: "strong"` | 剥离 |
| 替代物 | 无 | 【追读设计三问】14 行 |

`prompt_diff.txt` 是逐行差异：删除 2 行钩子字段 + 50 行 YAML + 2 行摘要标签，加入 14 行三问。

三问的实际文本（Prompt 第 30-43 行）：

1. **本章开始时，读者主要期待什么？**——素材取自 `urgent_loops` 里最紧急的未闭合问题、章目标、阻力与代价。
2. **本章实际满足、改变或反转了什么期待？**——必须落在六种可见形态之一（回答/行动/关系/新事实/代价/推翻认知），并声明“不能由叙述者额外补一句”。
3. **因为本章发生的事情，读者现在更想知道/看到什么？**——取自章纲的未闭合问题，但要求“以本章实际发生的事为准，接不上就不要硬加”。

边界句明确写了：**不要求每章 cliffhanger、爽点或反转**；过渡/铺垫章也要有当章回报，但不需要制造本章没有的高潮。

若素材缺失，三问会显式标注“（前情没有未闭合问题，本章可以建立一个）”，
而不是由 Runtime 编一条（`test_reader_pull_block_marks_missing_material_instead_of_inventing_it`）。

## 二、盲评

顺序互换，评委只看到两份稿子和同一份评分表，不知道 X/Y 对应哪一版；
`blind_key.json` = `{"X": "B", "Y": "A"}`。

### 第一轮：作废

第一轮两稿都写成了“昨天递过调阅申请并被驳回”，与第 2 章 Canon（没有递申请，窗口只出现“限制查阅”红字）冲突；
A 稿还漏了“老周打电话”的动作。评委读的是有缺陷的稿子，整轮作废，见 `eval/round1_invalidated.md`。
作废轮记录下一个方法学现象：**两名评委都选了自己先读到的那一稿**，位置偏差很强。

### 第二轮：有效

两稿都按 Canon 修正后重跑，评委换了新的、未接触过前一轮的实例。

| 维度（5 分制） | 评委 XY：B / A | 评委 YX：A / B | 第二轮合计 B / A |
|---|---|---|---|
| 1. 阅读吸引力 | 4 / 3 | 4 / 4 | 8 / 7 |
| 2. 是否更想继续读 | 4 / 3 | 4 / 3 | **8 / 6** |
| 3. 当章回报 | 4 / 3 | 5 / 4 | **9 / 7** |
| 4. 章末期待自然 | 4 / 3 | 4 / 4 | 8 / 7 |
| 5. 剧情推进 | 4 / 3 | 4 / 4 | 8 / 7 |
| 6. 人物主动性 | 5 / 3 | 5 / 3 | **10 / 6** |
| 7. 总体文学质量 | 4 / 3 | 4 / 5 | 8 / 8 |
| 8. 机械钩子（5=自然） | 4 / 3 | 3 / 5 | 7 / 8 |
| **合计** | **33 / 24** | **33 / 32** | **66 / 56** |

两轮顺序下**评委都选了 B**。其中 YX 评委是在第二读到 B 的情况下选的 B——
这是两轮里第一次有评委没有选自己先读的那一稿，说明第二轮的选择不是纯粹的位置效应。

但两名评委的**理由不同**，这比分数本身更重要：

- **XY 评委**认为 B 赢在因果链闭合：自造筹码（差异说明）→ 可量化的传导（三十九分钟）→
  真实损失（纸收不回来）→ 认知升级（从“卷宗被限制”到“我在被看着”）→ 可执行的下一步。
- **YX 评委**只给 B 微弱优势（33:32），认为 B 赢在“想点下一章”“当章回报”“主动性”，
  但在**文学质感**和**钩子自然度**上明确判给 A（A 的 7、8 项拿 5/5，B 只有 4/3）。

### 关键判断：是“回报”改善了，还是只多了个钩子

是**回报**改善了，不只是钩子：

- “当章回报”在两轮顺序里都是 B 高（4>3、5>4）。
- 两名评委独立列出了 B 本章实际兑现的东西：老周对两项差异的口头解释、上报被科长一句
  “人家的电话都打到我这儿了”坐实、主角付出了一张纸的代价、从登录记录推出删除者不是自己账号。
- A 的回报被 YX 评委描述为“主要是确认自己被看着，信息增量少”。

### 套路化

没有一版出现“正文空转、结尾硬挂悬念”。但 **B 的收尾更用力**，这正是第八项的分数来源：

> 现在他有一件可以做的事了：查清楚谁能在四十分钟里删掉一条查询记录。

YX 评委把这类句子判为“作者替角色总结任务”，B 因此在该项只得 3 分；
XY 评委则认为这句话“有据可依，且同时是一个人物决定”，不算硬加。**评委在这一项上直接分歧。**

A 没有这个问题，但代价是收束过静（YX 评委：“读完是点头，不是翻页”）。

## 三、判定

按预设规则：“若 B 明显更好 → `READER_PULL_LAYER_SUPPORTED`；若基本持平 → `NOT_PRIMARY`；
若 B 更差或套路感更强 → `OVERCONSTRAINED`”。

- B 在**追读相关维度**（想继续读、当章回报、人物主动性、剧情推进）两轮全胜或打平，方向一致；
- B 在**文学克制维度**（总体文学质量、钩子自然度）一胜一负，证据分裂。

结论是 **`READER_PULL_LAYER_SUPPORTED`**，但必须把结论限定为一句话：

> 追读三问能让 Writer 把“读者的期待 / 本章的兑现 / 新生的期待”变成可执行的三件事，
> 并提高当章回报与人物主动性；它不提高文学质感，且有让章末变成“作者宣布任务”的风险。

不是 `NOT_PRIMARY`：如果它只是换个说法，追读维度不会在两轮顺序里一致偏向 B。
不是 `OVERCONSTRAINED`：两版都没有被迫制造 cliffhanger，B 也没有变成机械钩子，
只是**有一位评委**认为它的收尾更用力。

## 四、限制

1. **n=2 名评委、1 个章节、1 个模型**。方向一致，但样本小；其中一名评委的差距只有 1 分。
2. **两稿不是同一 Writer 实例的两次采样**，而是同一 Prompt 的两次独立起草。
   字数也不同（A 2059 字 / B 1983 字），B 更短。
3. **第一轮作废暴露了位置偏差**，第二轮只有一个反例，不能充分排除。
4. **收尾用力（over-explanation）无法归因到三问本身**。它可能是第 3 问的措辞诱导，
   也可能只是这个 Writer 在拿到更明确的材料后自然更爱下结论。n=1 稿不足以下结论，
   因此本 PR **没有**为了掩盖它去改三问的措辞——改了就使被验证的 Prompt 与被交付的 Prompt 不一致。
5. **文学质量分不是目标函数**。本轮只回答“追读链是否成立、吸引力是否提高”，
   不回答“小说是否更好看”。

## 五、发现的其他缺陷（未在本 PR 修复，记录在此）

1. **键名不匹配是潜伏地雷**。`context_manager` 生产 `guidance_items` / `methodology`，
   `chapter_runtime` 消费 `items` / `strategy_card`。目前“每 600-900 字微兑现”“章首 300 字”
   没有进入 Writer，是**偶然**，不是设计。本 PR 删掉了消费端的死代码并加了注释警告，
   但没有改生产端——修键名会让无依据的字数位指令复活。
2. **第 3 章 Brief 与第 2 章 Canon 不一致**。Brief 写“调阅驳回记录被删”，
   Canon 写的是“没有递申请，只有一条限制查阅的查询记录”。两稿正文都是按 Canon 写的，
   说明 Writer 在纠 Brief 的错——这是 Brief 生产端的问题，不是本层的问题。
3. **`reading-power-taxonomy.md` 有 HARD-001~004（MUST_FIX）**，与它自己开头的
   “不做硬性评分裁决”矛盾，也与“Reader Pull 不设 blocking gate”冲突。本轮只在文档里标注为诊断标签。

## 六、CR 与决策呈现（13 问）

1. **一共多少个机制**：24 个（`00-inventory.md` 第二节全表）。
2. **哪些重复**：四套钩子枚举、四套“期待/伏笔”账本、四套兑现频率。
3. **哪些冲突**：`scene-sequel` 说缺失字段是 BLOCKER 而代码记 warning；
   `reading-power-taxonomy` 自称不裁决却定义 MUST_FIX；
   3000 字章高光结构与 15-beat 前四章铺陈冲突；`constants.md` 与 `chapter-planning` 字数不一致。
4. **哪些没有真正运行**：`writing_guidance` / 方法论策略卡（键名不匹配，从未渲染）、
   `checklist` / `reader_signal`（不进 Prompt）、`rhythm_curve`（更新函数无调用者）、
   `pacing_config`（零消费者）、`expectation_debt`（恒空）、`promise_ledger`（空）、
   Strand Weave、`thematic_echoes`（前四章不触发）、`taxonomy_excerpt`（读了不渲染）、
   `chapter-planning` 的爽点/结尾钩子/字数/主线剧情字段（parser 不识别）、`constants.md`（零引用）。
5. **保留/合并/降级**：KEEP 3（`urgent_loops`、章纲未闭合问题、`foreshadow_chain` 回收段）；
   MERGE 3（`hook_type`→第 3 问，微兑现概念→第 2 问，方法论施压/释放→题材倾向且删分数）；
   DEMOTE 4（爽点配置、`checklist`、`reader_signal`、`reading-power-taxonomy` 降为诊断）；
   REMOVE_FROM_RUNTIME 5（`hook_strength`、题材 `hook_config`、写作指导基线、`reference_hints[0]`、`pacing_config`）；
   DORMANT 9（节奏曲线、期待债务、`promise_ledger`、主题回声、Strand Weave、chapter-planning 字段、
   `constants.md`、3000 字结构、MRU/McKee 等 Tier 2/3 工具）。
   删除历史理论文档：一个都没有——dormant 的只标注，不删。
6. **Writer 现在收到什么**：章目标/阻力/代价、Scene 四问、**追读三问**（自然语言，含素材）、
   治理 Canon、Creative Brief、工艺约束、前情线索。**不再收到**任何 YAML 参数、强度基线、
   密度阈值、爽点频率、`hook_type` 标签。
7. **与 Scene 四问怎么连接**：Scene 四问管“这一场怎么走”（目标/冲突/转折/变化）；
   追读三问管“读者为什么翻页”（期待/兑现/新期待）。三问的第 1、2 问直接复用 Scene 四问的
   目标与变化字段作为素材，第 3 问接 Scene 第 4 问的“什么已经发生实质变化”，
   所以两层不是并列的清单，而是同一份章纲的两种读法。
8. **单变量**：`--reader-pull` 开关（同一指纹，同一 Brief，同一 Scene 设计）。
9. **B 是否更可读**：是，但有限。两轮顺序都偏 B（66:56），追读维度一致；
   文学质感一胜一负，一名评委只给 1 分优势。
10. **回报是否改善**：是。当章回报两轮都更高，评委独立列出了四项实际兑现（解释、坐实上报、付出代价、登录记录排除）。
11. **是否套路化**：没有强制 cliffhanger，两版都覆盖四个必写节拍；B 的收尾有一处“替角色宣布任务”，
    一名评委据此扣分（B 3 / A 5），另一名评委认为不算（B 4 / A 3）。
12. **Reader Pull 是不是下一个真正的瓶颈**：**不是了**。本层解决了“Writer 不知道读者在等什么”的问题；
    剩余方差出现在散文执行（该不该把结论说出口）和上游素材（Brief 与 Canon 不一致），
    而不是缺少更多追读机制。再加机制只会加重参数化。
13. **PR / HEAD / CI**：见交付时的最终回复（分支 `fix/reader-pull-layer`，单 PR，不直接合并）。
