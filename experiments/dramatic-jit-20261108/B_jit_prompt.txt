## 3. 创作策划任务书 (Creative Brief)
一、开篇委托

《根源牌序》第 4 章《室友的邀请》。一句话：陈默带着一个双人副本的活儿回来，林川在闸门落下前必须决定，是拿钱走人，还是回头把队友捞出来。

二、这章的故事

五月三日下午，宿舍。距旧矿道那场抢怪和 PVP 只隔一天。林川的余额还停在九十八根源碎片，木盾碎在损坏栏里，修一次要一百二十；灰獾昨天放的话是“后天矿道换我们队值守”，也就是明天，旧矿道这条收入线就要断。他下午没有别的活，坐在电脑前算账，越算越紧。

陈默拖着箱子回来。他五月一日走的，桌上那半袋饼干早吃完了，空袋子还夹着晾衣夹。他进门先放下一袋从家里带的东西，看见林川屏幕上的损坏栏，没问“你怎么混成这样”，只问了一句“盾还没修？”然后把自己的事说了：他接了一个双人首通委托，原搭档临时跑了，今晚之前凑不齐人，委托作废，前期刷本和准备的时间也白费。他需要一个人在他压住配重闸门的时候，穿过升降平台去拆主齿轮。他知道林川在玩这个游戏，做代练，最近缺钱，也知道室友之间有这点信任；他没有提什么“看过你的战绩”，只是问“你下午有空没有”。

林川的第一反应不是答应，是算账：首通奖励多少、护符归谁、碎片怎么分、如果失败谁赔。陈默把丑话说在前面：这个副本有点坑，攻略写的是四十秒，实际不一定；原搭档就是被机制坑走的。他没有隐瞒风险，但也没有把全部细节说死——他自己也只打过前半段。

林川最后还是答应了，理由很实际：他需要钱，而且他确实想知道自己那张卡在真正的机关副本里能走到哪一步。进本前两人把分配说清楚：首通奖励四十碎片，加一件坦度护符；护符归陈默，碎片一人一半。林川还加了一句：如果临时掉别的东西，谁用得上归谁，用不上卖掉再分。

副本叫“旧城升降井”。前半段是废弃的齿轮井道，锈蚀的机关傀儡沿着轨道巡逻，陈默顶在前面，林川拆升降平台的气压阀和卡死的齿轮。两人第一次配合，谈不上默契，但都能看懂对方在干什么：陈默不抢林川的机关，林川也不在陈默拉怪的时候乱动。中途有一个小坎——升降平台升到一半卡住，林川要爬到平台底下拆限位器，陈默得在下面顶住不断刷新的傀儡。林川在平台底下听见陈默的盾被砸得一下一下响，手上的动作快了一拍。这是他们第一次把后背交给对方，但两个人都没说出来。

最后一道闸门前，攻略说陈默压住配重，林川有四十秒穿过平台拆主齿轮。陈默站上配重，让林川先走。林川跑到一半，闸门在第二十五秒就开始落——攻略是错的。陈默还在门后，血条在掉，他的盾卡在闸门和地面之间，退不出来。林川已经看见主齿轮了，再往前几步，首通就是他的；按他进本前的算法，这时候回头是最不划算的：奖励要重新分，自己还可能被关在里面。

他往撤离口跑了两步，听见闸门落下的声音，又折回来。他用鲁班机关术拆开闸门的限位齿轮，把门卡住。系统给那个齿轮的标注是“不可拆解”，他的卡却认了。陈默从门后滚出来，两个人一起把主齿轮拆掉。升降井反向坠落，他们踩着最后一段平台爬回出口。

首通成立。系统结算：四十碎片，一件“则级·铁壁护符”。陈默需要那件护符，林川说“东西归你，碎片一人一半”。陈默要把四十碎片全给他，林川只拿二十。他的余额从九十八变成一百一十八，离修盾还差两块。陈默要再给他十块，他没要。

出本以后，陈默没有立刻说谢谢，先问了一句：“你刚才拆那个齿轮，系统不是标了不可拆解吗？”林川说代练做久了，什么机关都摸过。陈默看了他两秒，没追问，只把好友申请发过来，说以后有活儿一起。林川点了接受。

本章必须让读者看见：陈默的邀请、两人的组队、副本的高难度、战利品的分配、首通成立、陈默对林川操作的好奇。不能解释地球卡、E-0001、记忆完整度、档案盒；不能让陈默知道林川的秘密；不能让木盾恢复或凭空换新盾；不能让赵公子、灰獾或其他势力在本章正面登场；不能让林川用出机关术卡面以外的技能。

三、这章的人物

林川：钱紧、时间紧、手里只有一张攻击力几乎可以忽略的机关术卡。他习惯先算再动，答应组队之前一定先把分配问清楚；进了本也不肯把全部控制权交出去。他不是热血型，不会因为“室友开口”就拍胸口答应。他真正的底线是“不把队友丢在门后”，但这条底线他自己不会用一句话说出来，只能让读者从他的选择里看见。他说话短，越到紧要关头越少话；对陈默的玩笑只回一半。

陈默：坦克型玩家，凡俗武学底子，块头大，说话直，但不傻。他不觉得自己在求人，也不觉得林川帮他是理所当然；他把风险先摆出来，是因为他不想再坑一个搭档。他需要这次首通，但他更在意“这个人下次还愿不愿意跟我打”。他看见林川拆限位齿轮时，第一反应不是惊呼，是算——一个刚玩两天的新号，为什么手这么稳。他把疑问压到出本以后才问，问得也不重。

副本：不是反派，是一套会收紧时间的机关。它不讲道理，只认承重、倒计时和齿轮的咬合。它的规则要在正文里让读者看懂：谁压门、谁过平台、为什么四十秒会变成二十五秒、为什么主齿轮拆掉以后升降井会反坠。不要用旁白解释机制，让角色在动作里发现。

四、这章的感觉与边界

基调贴着前三章：冷、实、克制。人在宿舍里对着电脑打，现实的手在鼠标上，游戏里的身体在井道里；不要让画面突然变成全息潜入或真人上场。战斗段可以收紧，短句、快切、少形容，但每次转折都要让读者看懂林川为什么这么选、这一步换来了什么。系统文本保持前两章的平直格式，不加感叹号，不让系统卖萌，也不写“叮”的一声。

最忌讳：靠旁白夸林川厉害；靠围观群众惊呼；靠“手速”解释胜利；让陈默变成只会喊“好操作”的捧哏；把副本机制写成一段说明书；把“信任”写成两个人互相说“我信你”。林川的强来自看懂结构、利用机关和敢在最后一刻回头，不是来自数值碾压。陈默的强来自他能扛、也敢先站上配重，不是来自给主角当背景板。

本章不能回答：地球卡为什么存在、E-0001 和“未登记”的伤害来源是什么、记忆完整度那条线到底是什么。那条线最多在机关术拆“不可拆解”齿轮时轻轻碰一下，让读者记住它还在，但不要解释、不要升级、不要再来一次第一章那种断电级异象。

本章可以回答也必须回答：这张卡在真正的机关副本里到底怎么用；一个只有一张烂卡、连盾都修不起的人，能不能靠脑子跟人配合；首通之后他要付什么账。

五、收在哪里

回报是双层的。明面上，首通成立，陈默的委托保住，两人正式成为固定队友；暗面上，林川证明了自己不是只能单刷，他可以在关键时刻把后背交给别人，也可以让别人把后背交给他。代价也清楚：他只拿二十碎片，余额一百一十八，离修盾还差两块；他在陈默面前露了一手不该会的东西；灰獾说的“后天”就是明天，旧矿道不能再去了。

读者拿到的是：主角不是靠系统发糖，是靠看懂机关和一次不划算的选择赢下队友；游戏里的信任有价格，而且价格具体到两块碎片。读者现在更想知道：陈默会不会继续追问那只齿轮；林川差的两块碎片怎么补；明天矿道换防，灰獾会怎么找他；以及那个“不可拆解”的标注，为什么对他的卡不起作用。

## 本章创作方法
（以下方法只在本章素材允许的范围内执行；与 Canon、作者意图、本章禁区冲突时，一律以后者为准。）
1. 副本拆成两到三次可追踪的交锋：每次先写清这一轮要拿到什么（清掉这波、抢到机关位、把仇恨拉回来），再写清什么真正挡住他们（怪的机制、木盾已毁、地形或时间），然后让某一方改打法并付出代价。不能只写掉血不写伤害从哪来——每一次掉血都要对应已经写明的攻击、机关触发或失误。
2. 陈默不能只在旁边喊小心或夸林川厉害。入本前让他自己算一遍收益和风险，副本里主动做一件只有他能做成的事（挡下一次攻击、看穿怪的机制、决定进退），并且这个决定要真正改变林川的处境。林川答应组队也得是先算过九十八块碎片和一百二十维修费之后的取舍，不是被室友一说就点头。
3. 邀请那场别写成陈默介绍副本、林川点头。让陈默绕开“我需要你”先问别的，比如还差多少修盾、单刷卡在哪；林川也别直接说愿意分战利品，先把分配和条件问具体。通关后陈默问“你的操作不像新手”，别让他一次问到底，让林川用一句反问或沉默挡回去。
4. 开场从木盾耐久归零和九十八块碎片的窘迫接上：林川今天必须先面对“没盾怎么打”这个具体问题，读者要看的是他会不会答应、这笔账划不划算。首通必须给出实打实的回报——任务完成、分掉一部分战利品、多出一个能继续一起打的人；结尾落在陈默对操作的那句疑问上，不要另起一件和本章无关的新麻烦。

## 6. 正文交付协议 (Handoff Protocol)
1. 输出连贯正文，严格按中文叙事逻辑组织；
2. 正文末尾必须严格附带合法的 <chapter_changes>...</chapter_changes> 结构化提案块；
   提案块必须是合法 JSON 对象，包含以下 8 个标准顶级字段：
   - character_state_changes (对象数组): [{"character_id": "角色名", "new_state": "状态变化", "importance": "normal"}]
   - new_plot_points (对象数组): [{"context": "情节发展描述", "importance": "normal"}]
   - foreshadowing_actions (对象数组): 若本章无既有伏笔操作填空数组 []
   - location_state_changes (对象数组): 若无填 []
   - faction_state_changes (对象数组): 若无填 []
   - time_progression (对象或 null): {"time_period": "时间进展描述", "importance": "normal"}
   - item_transfers (对象数组): 若无填 []
   - unresolved_questions (对象数组): [{"question": "章末悬念或未决问题"}]
   注意：各数组元素必须为 JSON 对象（严禁输出纯字符串数组），若无变更请使用空数组 []；
   【状态变化 vs 首次登场核心契约】：
   - 新角色/新地点/新物品可以正常出现在正文中；
   - 首次出现的新实体不属于 state change，后续由 Data Agent 根据最终正文独立提取，并在 ChapterCommit acceptance 后进入正式账本 projection 入库；
   - 提交前，严禁把尚未入库的新角色/新实体写入 character_state_changes, location_state_changes, faction_state_changes, item_transfers 等状态变更字段（若无已有实体变更，填空数组 []）；
   - new_plot_points.involved_characters 当前受 R3 门禁约束，只填写 Canon/context 中【已经存在】的角色，严禁填写尚未入库的新角色；
   - 新角色参与的事件仍完整记录在 new_plot_points 的情节描述（context 或 description）中；
   - 极短示例：正文首次出现新角色“巡查队长赵崇”与新地点“地下档案修复室”：
     正确: "character_state_changes": [], "location_state_changes": [], "new_plot_points": [{"context": "林越在矿道遭遇巡查队长赵崇罚没产量", "involved_characters": ["lin_yue"]}]
     错误: "character_state_changes": [{"character_id": "zhao_chong", ...}], "new_plot_points": [{"involved_characters": ["lin_yue", "zhao_chong"]}]（尚未入库的新角色写入 state change 或 involved_characters 会被 R3 门禁阻断拒绝）；
   枚举白名单约束（违规将直接被门禁拦截）：
   - 所有 importance 字段值只能取: "normal", "important", "critical"（严禁使用 "high"/"low"/"medium" 等）；
   - foreshadowing_actions.action 只能取: "setup", "payoff"；
   - item_transfers.new_status 只能取: "active", "lost", "destroyed", "sealed"；
