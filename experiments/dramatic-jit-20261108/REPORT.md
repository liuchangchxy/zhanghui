# 临写前 JIT Dramatic Planning A/B — 第 0004 章实验报告

## 0. 结论摘要

**PRIMARY QUESTION：把 Zhanghui 现有分散的戏剧设计能力集中到“临写前 JIT Dramatic Planning”，是否能让 Writer raw 明显优于当前正式流程？**

**三选一结论：`JIT_BETTER`（有条件）。**

- 两位盲评 Judge（fable / opus，位置反转）都选 **X = B（JIT）**。
- B 的优势集中在人物主动性、选择/代价、因果推进、Turn、Consequence；不是靠文笔。
- **但本次有一个实验设计缺陷**：冻结的 Hard Intent 里被加入了一条“不给木盾恢复”，而章纲和 A 的生产 brief 都没有这条；A 是在修盾合规的前提下写作的。两位 Judge 都把这一条当成硬规则，因此“木盾差异”不能算 JIT 的证据。剔除它之后，B 仍在 Turn、折返选择、陈默动机、固定关系落点、经济尺度上占优，所以结论仍为 `JIT_BETTER`，但优势幅度必须打折。
- 这不是一次干净的“证明”；它足以支持下一阶段先改**临写前戏剧规划**，不足以支持立刻正式重构。

1. **Turn**：B 的“四十秒攻略”在 25 秒失效（锈链），闸门提前下落、陈默被困，计划被推翻；A 的每一关都按陈默给的情报顺利执行，没有真正的 plan invalidation。

3. **后果**：B 结束在 118/120、木盾按钮仍是灰的、陈默的盾没了、好友关系建立；A 修好木盾、余额 238，结尾是“明天七点入口见”的钩子。
4. **人物主动性**：B 的陈默有客户截止时间、原搭档退出、先把风险说清；A 的陈默主要是“卡本里了”的机制解说员和坦克。
5. **邀请方向**：B 是陈默发邀请、林川接受；A 写成林川点组队邀请，与“陈默发出邀请”的 must-cover 有偏差。
6. **固定队友关系落点**：B 有好友申请 + “以后有活我先问你，碎片五五”；A 只落到“明天七点入口见”，是下一次约定，不是已建立的固定关系。

## 4. 人类终判

### 4.1 三选一

**`JIT_BETTER`（有条件）。**

理由：即使把“木盾差异”整体剔除，B 仍在 Turn、折返选择、陈默动机、邀请方向、固定关系落点、经济尺度上优于 A；A 的优势主要在阅读爽感（Judge 2 给 A 的 READING_APPEAL 5）和部分句子的干净程度。用户关心的五个戏剧维度中，B 赢了四个半（选择/代价这一项因木盾混淆要打折）。

### 4.2 3–6 个真正决定结果的正文差异

**差异 1：B 有真正的 Turn，A 没有。**
B：`攻略写四十秒，实际不一定` → `右上角的数字跳到25。闸门动了。` → `配重链在抖，一节链环从齿槽里滑出去。攻略上的四十秒，指的是新链。` 原计划当场失效，目标从“通关”变成“救人”。
A：双链闸→锈齿鼠→铆钉傀→守井傀，每一关都是“陈默给情报/扛住，林川用机关术拆一个点”，包括 `它砸完会顿一下`、`链子一紧，它就只能往前`。没有一处让原计划失效，只有信息更新后继续执行。

**差异 2：B 的选择有可见损失面，A 的选择被写成理性最优解。**
B：`撤离口在平台右侧，十二步。主齿轮在正前方，五步。他往撤离口跑了两步。……他折回去，跑回闸门下。` 代价是首通记录可能作废、陈默的盾 `被闸门咬成两半`。
A：`下次则级卡归我`、`卡归我，我从我那份里补你八十`，随后文本自己算账：`现钱、修好的盾、一个明天还愿意一起进本的人——这三样比一张要等买家的卡实在`。选择存在，但被提前论证成划算，没有现场的两难。

**差异 3：B 的后果留到章末且跨章，A 的后果在章内被结清。**
B：`余额跳了一下。一百一十八。修复价格还是一百二十。`、`木盾的修复按钮还是灰的。`、`陈默……把盾……被闸门咬成两半`，固定关系用好友申请落地。
A：`木盾耐久跳回3/3，他重新装备`、`三百五十八减一百二，二百三十八`，最后落在 `明天旧矿道换灰獾那队值守。七点，入口见` 和 `打完明天那场，再说`——这是钩子，不是本章事件留下的后果。

**差异 4：B 的陈默有独立动机，A 的陈默更像任务派发器。**
B：`客户要今晚十二点前的首通记录。他原来的搭档昨天退了。`、`机制坑。攻略写四十秒，实际不一定。他打了两趟，第二趟把修理费赔进去了。`、`失败呢？算我的。按代练价结你，不让你白跑。`
A：`卡本里了。断链矿井，二人本。`、`双链闸。左右两个绞盘隔十二米，三秒内同时拉下。我一个人跑不过来。` 陈默承担了大段机制解说；他的“邀请”动机只有“卡本里了”。

**差异 5：A 把组队邀请的方向写反/写含混，B 对上了 must-cover。**
A：`林川看了一眼装备栏里灰着的木盾，点了组队邀请。`——邀请由林川发出，和“陈默邀请林川”冲突。
B：`陈默发来组队邀请。林川点了接受。`——方向正确。

**差异 6：奖励尺度与前文经济。**
B：首通 `根源碎片×40`，和第三章“矿道一趟净赚三十到四十”同量级；20 块正好卡在 98→118、差 2 块修盾。A：`首通三百六碎片` + 则级卡 + 矿脉铁，林川分 260，一章内把前三章的“穷”全部抹平，并让第五章“被迫逃离安全区、损失游戏币”的压力提前失效。
（注：`则级·青铜战犬` 在 A 的 sealed package“本章相关物品”里已出现，不是 A 完全凭空发明；但 360 碎片的尺度是 Writer 临场定的。）

### 4.3 关于“木盾差异”的自我更正

冻结的 Hard Intent 写了 `不让木盾恢复或凭空换新盾`，Judge 1 和 Judge 2 都把它当作硬规则，并把它列为第一差异。但：

- `大纲/第1卷-详细大纲.md` 第 4 章没有“不给木盾恢复”这一条；
- A 的真实生产 brief（`.webnovel/tmp/creative_brief_0004.txt`）只写 `木盾耐久为0/3，修好前不能继续装备`，没有禁止修复；
- A 在 `断链矿井` 首通后拿到 260 碎片，去维修台修盾，是对其自身输入的合规行为，不是越界；
- 这条禁令是实验者在构造 B 的 Hard Intent 时加入的，B 收到了、A 没有收到。

因此：**“木盾修没修”不能作为 A 的缺陷，也不能作为 B 的优势。** 这是本次实验最大的方法缺陷。它会影响两位 Judge 的第一差异和部分选择/代价评分；我在 §4.1 的结论中已把它整体扣除。即便如此，差异 1、2（折返选择本身）、4、5、6 仍然独立成立。

## 5. 六个指定问题

**1. B 的人物是否更像自己在做决定，而不是执行剧情？**
是。B 的林川自己开条件（`临时掉的东西，谁用得上归谁；用不上，卖了再分`）、自己在闸门下折返、自己退回多给的十块；陈默有客户、截止时间、前搭档退出的独立压力，并先讲风险再问“你下午有空没有”。A 的林川战术上主动，但关键输入由陈默喂到嘴边（弱点、链子绷紧、三秒），陈默的主要功能是解说机制和扛伤。

**2. B 是否有真正的选择和代价？**
有，但有一处要打折。核心选择是闸门下“撤离口十二步 vs 主齿轮五步”，他先跑两步又折回；代价是首通记录可能作废、陈默的盾被毁。第二个选择是退回多给的十块，余额停在 118、差 2 块修盾。后者与“木盾不恢复”的实验约束重合，不能全部算作自然选择；但折返选择独立成立。A 的选择（让卡换 80）在文本内被算成净赚，修盾后余额 238，代价被立即对冲。

**3. B 的 Turn 是否真正改变了场景？**
是。25 秒链条打滑、闸门提前下落，让“四十秒攻略”失效，陈默被困，林川从“通关”转为“救人”，并被迫对 `不可拆解` 的限位齿轮动手。A 的“守井傀胸口回血”只是信息更新，计划仍是“引到吊斗下—卸棘轮”；三关都按同一模板顺利执行。

**4. B 的 Consequence 是真实后果，还是章末钩子？**
是真实后果。B 章末：余额 118、修复价 120、按钮仍是灰的；陈默的盾被闸门咬成两半；好友关系已建立；`不可拆解` 的系统记录留在屏幕上。A 章末：木盾 3/3、余额 238，压力清零；`明天七点入口见` 和 `打完明天那场，再说` 是把问题推到下一章的钩子。

**5. B 是否减少了无意义填充？**
没有明显减少，两位 Judge 判断不一致：Judge 2 认为 A 的填充更少，Judge 1 认为 B 略少。我的读法是：B 的开头账目、馒头咸菜、空饼干袋是生活细节，但进入邀请偏慢；A 的三段副本结构对称、每段同一解法、“三秒”重复三次，是功能性重复。两边都有填充，类型不同，不能算 B 的净优势。

**6. B 是否“设计感太重”？**
有，但不是最主要的问题。B 的设计感集中在账本上：118 对 120、折返“两步”、`不可拆解` 齿轮 + 卡面小字、`他后来没解释这两步` 这类作者旁白。Judge 2 明确指出“退回十块像是为了守住木盾不恢复的约束而设计”。A 的设计感更结构性：三段教学关式副本、陈默成段解说、`三秒` 反复出现。两者都“有设计”，A 更像流程模板，B 更像被精心守住的一笔代价。B 的 brief 本身没有泄漏 JIT 方法名，这一点是干净的；问题在正文的算术和巧合，不在方法论泄漏。

## 6. 哪些戏剧能力真的提升了

| 能力 | 判断 | 证据 |
|---|---|---|
| 人物主动性 | **提升** | 陈默有客户/截止/前搭档压力；林川自己定分配规则、自己折返、自己退回多给的钱 |
| 选择与代价 | **提升（打折）** | 折返选择独立成立；118/120 的代价与实验约束重合，不能全算 |
| 因果推进 | **提升** | 锈链→25 秒→闸门落→陈默被困→折返→拆限位齿轮，因果链闭合；A 是三关顺序解题 |
| Scene Turn | **提升** | 攻略失效、目标改写；A 无 plan invalidation |
| Consequence | **提升** | B 的后果跨章可见；A 在章内结清 |
| 阅读吸引力 | **未提升/略降** | Judge 2 给 A 5、B 4；A 更爽、更有战斗奇观 |
| 自然度 | **大致持平** | Judge 2 两稿都 4；B 有作者旁白和慢开头，A 有模板化三关 |
| 无意义填充 | **大致持平** | 类型不同：B 生活细节多，A 功能性重复多 |
| 文笔 | **不是本实验目标** | A 的句子更紧；B 有几处文学腔旁白 |

## 7. 架构诊断（只读，不改代码）

完整版见 `architecture_diagnosis.md`。核心表：

| 决策 | Current owner | B owner |
|---|---|---|
| Hard Intent | 章纲/planner；第 4 章只有自然语言字段，无结构化 must-cover/forbidden/scene | 实验固定，不变 |
| 人物即时目标 | Context Agent 给泛化动机；具体目标 Writer 临场定 | JIT Planner |
| 冲突如何发生 | Writer 临场定（副本类型、谁挡谁、机制如何咬合） | JIT Planner |
| 关键选择 | Writer 临场定 | JIT Planner |
| 代价 | Writer 临场定 | JIT Planner |
| Turn | Writer 临场定 | JIT Planner |
| Consequence | Writer 临场定 | JIT Planner |
| Reader payoff | Runtime 追读三问 + Writer；三问只重述章级字段 | JIT brief（不再注入三问） |
| 表现方法 | Skill Router + Writer | Skill Router + Writer（不变） |

关键观察：

1. **第 4 章没有结构化场景字段**：无 `scene_*` / `sequel_*`，`plot_structure` 为 `{}`。Runtime 的“场景四问”只能回退到章级 goal/obstacles/cost/change，是同一批字段的另一种问法；“追读三问”也是重述。
2. **Context Agent 与 Runtime 重复同一内容**：Writer 在一份 prompt 里至少三次看到同一批章级事实，但没有一次看到“谁先出招、谁阻止谁、有哪几个真实选项、代价是什么、什么让计划失效、场景结束时什么改变”。
3. **Context Agent 被事实边界约束**：A 的 brief 明写“副本名称、具体敌人、掉落及分配比例尚无确定依据”，它不能发明副本，于是只能给泛化建议，把具体戏剧设计留给 Writer。
4. **Skill Router 本次没有越权**：4 个 skill 的 guidance 主要是表现层（“副本拆成两到三次可追踪的交锋”“陈默不能只在旁边喊小心”），没有决定关键选择/Turn/Consequence。它不能填补戏剧设计的真空。
5. **Writer 是事实上的戏剧设计者**：副本、冲突、选择、代价、Turn、Consequence 都在起草时临场决定。这是本章戏剧设计的实际发生位置。
6. **8–12 章提前规划的 soft Scene 字段不是“过时”，而是“缺失”**：本次没有可用的场景设计，Runtime 的 fallback 不能替代。
7. **Reviewer / Finalizer / Data Agent 都在下游**：Reviewer 能在事后指出“战斗因果不清”，Finalizer 删解释、提潜台词，Data Agent 记录事实；它们都不在写前提供选择/代价/Turn。

## 8. 是否进入正式集成

**不立即正式重构。** 本轮结论只支持“方向成立”，不支持“直接改生产”。

下一轮建议的最小集成（仍然只是实验，不是正式架构）：

1. 在 Context Agent 之前或之内增加一个**临写前戏剧规划步骤**，输出两件东西：结构化的 Hard Intent、压缩后的 JIT Creative Brief；不新增 Agent、不加 Gate、不建数据库。
2. **Hard Intent 必须从章纲 + accepted Canon 机械推导**，不能由实验者按偏好添加；`forbidden` 必须显式列出并被 A/B 双方收到。
3. Writer Prompt 只多一个 brief 段；`--scene-design` / `--reader-pull` 的二选一或去重，需要单独实验，不能和 JIT 混在一起。
4. Writer、Skill Router、Finalizer、Reviewer 本轮都不动。
5. 用 3 章、每章每臂 1 次生成做干净复现；如果 B 在 Turn/选择/代价/Consequence 上继续稳定胜出，再讨论正式集成。

**不该做的事**：因为这一章 B 更好，就立刻加长 Writer Prompt、给 Finalizer 加轮次、给 Reviewer 加维度。这三者都在下游，解决不了“戏剧决策发生得太晚、由 Writer 临场做”的问题。

## 9. 对最终问题的明确回答

> **这次实验是否证明：Zhanghui 下一阶段真正该改的是临写前戏剧规划，而不是继续增加 Writer Prompt、Finalizer 或 Reviewer？**

**不能说“严格证明”，但方向成立，且证据指向“先改临写前戏剧规划”。**

支持这一判断的，不只是盲评 2:0，还有三条独立证据：

1. 当前第 4 章没有可执行的场景设计；Runtime 的四问/三问只是章级字段重述，Writer 必须在起草时临场决定冲突、选择、代价、Turn、Consequence。
2. B 的 brief 没有泄漏任何方法名，Writer 只看到故事；但 B 的正文在 Turn、折返选择、陈默动机、固定关系落点上明显更像“人物自己在做决定”。
3. A 的三段副本是同一解法的重复，且把经济压力在章内结清；这不是“Writer 不够努力”，而是“关键戏剧决策没有在写前被决定”。

但必须保留三点限定：

- n=1 章、每臂 1 次生成，不能排除采样偶然；
- “木盾不恢复”是实验者加入的、A 没有收到的约束，盲评的第一差异被污染；这是一次方法错误，下一轮必须修正；
- 两位 Judge 同属 Anthropic 家族，非 Anthropic Judge 不可用，厂商级偏好无法排除。

因此，正确的下一步不是“正式重构”，而是：**先修正 Hard Intent 的推导与对称性，做 3 章干净复现；如果结论稳定，再把临写前戏剧规划做成最小生产集成。** 在这之前，继续增加 Writer Prompt、Finalizer 或 Reviewer 的优先级应低于临写前戏剧规划。

## 10. 限制清单

- 单章（第 0004 章）、每臂单次生成；没有重复采样，不能估计方差。
- Hard Intent 不对称：`不让木盾恢复` 是实验者加入的，A 的生产 brief 没有；两位 Judge 的第一差异因此被污染。已在 §4.3 扣除。
- Writer 不是跨臂盲写：同一模型、同一参数，但 A/B 看到不同 prompt；无法排除“B 的 brief 更具体”本身带来的注意力效应。
