【场景设计四问】
把本章当成一场戏来写，动笔前先回答下面四个问题；答案只能来自本章规划，不得自行加设定。

【追读设计三问】
本章的追读链只由三件事决定。动笔前先回答问题，再让它们在正文里成立；答案只能来自本章规划与前情，不得自行加设定。
1. 本章开始时，读者主要期待什么？
   - 读者现在最想知道：登录界面重新铺满时，背景闪出一行不在界面任何一层、字形不像游戏字体且边缘有毛刺的字：“你从哪里来？”。林川伸手去按截图键时画面消失。

## 3. 创作策划任务书 (Creative Brief)
**一、开篇委托**

《根源牌序》第0004章《室友的邀请》：陈默邀请林川组队，两人付出分享战利品的代价，凭配合首通高难副本，并建立固定队友关系。

**二、这章的故事**

上章五月二日晚，林川在旧矿道完成三只灰背豺委托，也在抢怪对决中击败灰獾。代价是木盾损毁：他有98根源碎片，维修需要120。鲁班机关术的战斗记录留下“最近一次伤害来源：未登记”；灰獾复活后放话，后天矿道换他所在的队伍值守，林川再来就要报复。章末林川仍在宿舍，游戏窗口切回了矿道。

本章从**2026年5月3日下午**展开，覆盖约三小时。交代与上章之间已经跨夜，再进入陈默的邀请；灰獾所说的“后天”是5月4日，不能提前写成已经发生的报复。本章没有倒计时，也没有指定反派。

开篇时，读者会关心林川缺盾、缺钱之后怎么继续游戏，也会期待独自作战的他遇到能够合作的人。陈默提出组队后，林川眼前想得到的是完成副本任务的机会和收益；真正挡在面前的是副本难度——单刷几乎不可能——以及组队就必须分出战利品的取舍。他接受合作，和陈默在副本中根据各自能做到的事行动、沟通、调整；两人的配合应当实际改变战局，让首通有清楚的因果。

本章结束前要兑现三件事：**完成副本任务、交代战利品分享的代价、让两人形成继续固定组队的关系**。信任从共同承担风险和各自有效的行动中长出来。副本名称、具体敌人、掉落及分配比例尚无确定依据，起草时不要把未经建立的细节当成既有设定。

能力与状态要接住前文：林川第一卡槽装备相级·鲁班机关术，第二卡槽空置；木盾耐久为0/3，修好前不能继续装备。机关术已表现出可拆解机关类物件、借环境造成伤害的能力；不要凭空扩展其功能，也不要让陈默无缘无故知道卡牌的隐秘来历。

前文留下的线索按紧迫程度留意，均是尚待回应的问题，不等于本章必须揭晓：

1. 第2章，鲁班机关术的来源、为何不在引导数据内，以及“继续探索”会解锁什么，仍未解释。
2. 第3章，机关术造成的伤害来源显示“未登记”；若本章再次以它造成伤害，注意与既有记录衔接。
3. 第2章，“地球”归属与编号E-0001不在林川所知的七大法则编号中，其意义仍未知。
4. 第1章，档案盒图标触发校验通过，记忆完整度显示0.01%；其来历和作用仍未知。
5. 第3章，灰獾的矿道报复之约尚未到时间，可保留压力，不抢走本章组队主线。

**三、这章的人物**

**林川**：账号“归乡人”，刚靠机关术完成首次实战，却损失了盾牌，余额不足以维修。他需要继续获得游戏资源，也面对高难副本单人难以完成的现实；接受组队意味着分享收益，并把一部分战局交给室友。保持他计算资源、观察环境后行动的习惯。说话简短务实，更多围绕眼前的判断和操作；对卡牌异常保持谨慎，不主动把尚未弄清的秘密解释成定论。

**陈默**：林川的室友，游戏ID“铁壁”。本章由他提出组队邀请，他也需要通过合作完成副本；让他在战斗中有自己的判断和有效行动，使林川有理由信任他。两人是已有生活接触的室友，对话可自然、直接。通关后，他对林川的奇怪操作产生具体好奇，可以问出“你的操作风格不像新手”；这份疑问应来自他亲眼看到的配合，不等于他已经知道机关术的秘密。

**四、怎么写更顺**

保持网游与卡牌故事的质感，核心是**规则清楚的竞技张力，其次是团队协作，再到胜利时的热度**。邀请和入本前的交代尽量短，让读者尽快明白副本为什么难、两人为什么值得合作；战斗段放慢到足以看清局势、操作、沟通与后果，再持续推进。赛后只留足篇幅交代结果、收益分配和关系变化。

让每一次关键配合都有可追踪的原因：一人面对什么局面、另一人做了什么、局势因此怎样改变。陈默不能只负责夸赞或喊话；林川的能力也不能靠突然增加效果取胜。上一章审读指出，对决中灰獾的掉血过程缺少可核验的伤害依据，本章尤其要让伤害、风险和胜负之间的关系清楚。

以林川的有限视角写陈默，借具体行动和回应呈现室友间逐渐建立的信任。情绪从上章获胜后的资源窘迫与警惕，转向尝试合作时的专注，最后落在通关后的踏实与一点被看穿操作习惯的微妙感受。近期没有可用的读者追读评分趋势；现有审读重点是战斗因果清晰。

**对标参考**：目前没有可用的具体对标资料。本章可依照游戏题材的共同期待，把难度、操作价值和最终收益写得可感知，让结果由副本进程和队友反应共同体现。

**五、收在哪里**

本章的回报是：林川和陈默完成了原本难以单刷的副本，林川分出了部分战利品，也获得了第一个固定队友；陈默通过共同作战，看到了林川不同寻常的操作方式。读者最初想看的“他能否在缺盾的处境下继续向前、两人能否配合”，在首通和组队关系中得到回答。

结尾落在通关后自然生出的交流上：陈默想知道，林川为什么会那样操作。这个问题来自本章两人的共同经历，也把读者的期待引向林川接下来会如何回应室友。

## 本章创作方法
（以下方法只在本章素材允许的范围内执行；与 Canon、作者意图、本章禁区冲突时，一律以后者为准。）
1. 副本拆成两到三次可追踪的交锋：每次先写清这一轮要拿到什么（清掉这波、抢到机关位、把仇恨拉回来），再写清什么真正挡住他们（怪的机制、木盾已毁、地形或时间），然后让某一方改打法并付出代价。不能只写掉血不写伤害从哪来——每一次掉血都要对应已经写明的攻击、机关触发或失误。
2. 陈默不能只在旁边喊小心或夸林川厉害。入本前让他自己算一遍收益和风险，副本里主动做一件只有他能做成的事（挡下一次攻击、看穿怪的机制、决定进退），并且这个决定要真正改变林川的处境。林川答应组队也得是先算过九十八块碎片和一百二十维修费之后的取舍，不是被室友一说就点头。
3. 邀请那场别写成陈默介绍副本、林川点头。让陈默绕开“我需要你”先问别的，比如还差多少修盾、单刷卡在哪；林川也别直接说愿意分战利品，先把分配和条件问具体。通关后陈默问“你的操作不像新手”，别让他一次问到底，让林川用一句反问或沉默挡回去。
4. 开场从木盾耐久归零和九十八块碎片的窘迫接上：林川今天必须先面对“没盾怎么打”这个具体问题，读者要看的是他会不会答应、这笔账划不划算。首通必须给出实打实的回报——任务完成、分掉一部分战利品、多出一个能继续一起打的人；结尾落在陈默对操作的那句疑问上，不要另起一件和本章无关的新麻烦。

## 6. 正文交付协议 (Handoff Protocol)
1. 输出连贯正文，严格按中文叙事逻辑组织；
2. 正文末尾必须严格附带合法的 <chapter_changes>...</chapter_changes> 结构化提案块；
   提案块必须是合法 JSON 对象，包含以下 8 个标准顶级字段：
   - character_state_changes (对象数组): [{"character_id": "角色名", "new_state": "状态变化", "importance": "normal"}]
   - new_plot_points (对象数组): [{"context": "情节发展描述", "importance": "normal"}]
   - foreshadowing_actions (对象数组): 若本章无既有伏笔操作填空数组 []
   - location_state_changes (对象数组): 若无填 []
   - faction_state_changes (对象数组): 若无填 []
   - time_progression (对象或 null): {"time_period": "时间进展描述", "importance": "normal"}
   - item_transfers (对象数组): 若无填 []
   - unresolved_questions (对象数组): [{"question": "章末悬念或未决问题"}]
   注意：各数组元素必须为 JSON 对象（严禁输出纯字符串数组），若无变更请使用空数组 []；
   【状态变化 vs 首次登场核心契约】：
   - 新角色/新地点/新物品可以正常出现在正文中；
   - 首次出现的新实体不属于 state change，后续由 Data Agent 根据最终正文独立提取，并在 ChapterCommit acceptance 后进入正式账本 projection 入库；
   - 提交前，严禁把尚未入库的新角色/新实体写入 character_state_changes, location_state_changes, faction_state_changes, item_transfers 等状态变更字段（若无已有实体变更，填空数组 []）；
   - new_plot_points.involved_characters 当前受 R3 门禁约束，只填写 Canon/context 中【已经存在】的角色，严禁填写尚未入库的新角色；
   - 新角色参与的事件仍完整记录在 new_plot_points 的情节描述（context 或 description）中；
   - 极短示例：正文首次出现新角色“巡查队长赵崇”与新地点“地下档案修复室”：
     正确: "character_state_changes": [], "location_state_changes": [], "new_plot_points": [{"context": "林越在矿道遭遇巡查队长赵崇罚没产量", "involved_characters": ["lin_yue"]}]
     错误: "character_state_changes": [{"character_id": "zhao_chong", ...}], "new_plot_points": [{"involved_characters": ["lin_yue", "zhao_chong"]}]（尚未入库的新角色写入 state change 或 involved_characters 会被 R3 门禁阻断拒绝）；
   枚举白名单约束（违规将直接被门禁拦截）：
   - 所有 importance 字段值只能取: "normal", "important", "critical"（严禁使用 "high"/"low"/"medium" 等）；
   - foreshadowing_actions.action 只能取: "setup", "payoff"；
   - item_transfers.new_status 只能取: "active", "lost", "destroyed", "sealed"；
